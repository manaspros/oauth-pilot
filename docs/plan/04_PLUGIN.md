## Skill `oauth-guide` — "how hard is it, what do I do next"

Frontmatter description (this is what triggers it): *Use when the user asks how to set up, register, verify or get approval for an OAuth app for a provider (Gmail, Slack, Salesforce, …), or asks how long or how hard it is to connect an app to their agent or Composio.*

Flow:
1. Parse the app name or URL and optional use case. If the user's repo has Composio code, grep for tool slugs (`GMAIL_`, `SLACK_` …) to infer `tools`.
2. **If the MCP tool `oauth_guide_start` is available**, start a run, poll status, then `oauth_guide_get`. Save to `./oauth-guides/<slug>.md`.
3. **Fallback (no MCP server running):** the in-session Elephant–Goldfish flow.
   - Research in-session with WebSearch/WebFetch, following the `docs_research` brief (copied into the skill). Write `./oauth-guides/<slug>.notes.md`.
   - Write the guide JSON following `${CLAUDE_PLUGIN_ROOT}/schema/guide.schema.json`. This is generated from core in T19 via `zod-to-json-schema`.
   - Spawn `oauth-goldfish` with ONLY the claims and sources. Apply its verdicts.
   - Render markdown.
4. Reply in chat with the verdict box, the **Start today** line, the 3 next actions, and which steps have `actor=agent`. Offer to run `/oauth-pilot:oauth-setup`.

## Skill `oauth-setup` — "do it with me"

Frontmatter description: *Use when the user wants Claude to actually create or configure an OAuth app (developer console, Composio auth config, .env) for a provider.*

Tier B (see 00_PLAN cut-line). Steps 6–7 exist only if T01 confirmed the custom auth-config API (D-API-3/4). Otherwise they print the dashboard steps for the user to do by hand.

Flow (each phase ends with a short checkpoint message):
1. **Load the guide.** Use `./oauth-guides/<slug>.json`, or run `oauth-guide` first.
2. **Plan the split.** Print a table of steps × actor and get one confirmation from the user.
3. **Draft artifacts.** Fill templates into `./oauth-guides/<slug>/`: privacy policy, scope justification, demo video script. Fill only what the guide's requirements need.
4. **Drive the console** with claude-in-chrome:
   - Open the developer console URL in a new tab.
   - Create the app with the guide's field values: name, homepage, **redirect URI = Composio callback URL**, scopes.
   - **Hand off and stop when** you hit a login, 2FA, CAPTCHA, payment, terms-of-service acceptance, or any "submit for review" button. Tell the user exactly what to click, then wait for "done".
   - Never type passwords. Never accept terms on the user's behalf.
5. **Collect credentials.** Ask the user to paste client ID and secret into `.env` themselves (`<APP>_CLIENT_ID`, `<APP>_CLIENT_SECRET`), or read them from the page only if the user explicitly says so. Never echo the secret back in chat.
6. **Composio.** Run `scripts/composio-auth-config.mjs --toolkit <slug> --env-prefix <APP>`. It writes `COMPOSIO_AUTH_CONFIG_<APP>=ac_...` to `.env`.
7. **Verify.** Run `scripts/composio-connect.mjs --auth-config $id --user-id test-user --wait`. The user opens the URL and consents. The script reports ACTIVE or the error. On error, look up `guide.blockers` by symptom and propose the fix.
8. **Record.** Append the outcome to `./oauth-guides/<slug>/setup-log.md`: what was done, by whom, and the result. If run inside this repo, it also feeds `docs/verification/` as `tested` evidence.

Safety rules (copy into SKILL.md verbatim):
- No secrets in chat, commits or logs. Check `.gitignore` contains `.env` before writing it.
- Stop at every human-only gate listed above.
- If a console page differs from the guide, say so and record it. That is a doc-drift finding.

## Agents

- `oauth-goldfish.md`: the EGM-style reviewer. Mandates: read-only, no conversation context, judge each claim only against its cited source (fetch it). Output per claim: verdict and a one-line note. Base it on the EGM `design_critic` mandate block (Apache-2.0, credit in README).
